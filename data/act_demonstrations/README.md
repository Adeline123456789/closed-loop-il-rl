# 先看这里：这个数据集到底有多少、里面是什么

这是在本项目 Isaac Lab FORGE 插销仿真中，由已训练的专家策略执行操作而记录的示教数据。这里保存的是观察、动作和操作结果；不包含训练算法程序。`act` 是最初的使用目的，其他算法适配这些输入/动作后也可以读取。

统计日期：2026-10-30。以下数量来自总清单及全部 5,640 个 `.npy` 文件的实际维度、类型和文件大小检查，不是根据文件夹名称推测。

## 数量，避免把“回合”“帧”“文件”混在一起

| 你要数什么 | 实际数量 | 具体含义 |
|---|---:|---|
| 完整操作轨迹/回合 | **376 条** | 每条是专家执行一次完整任务回合的连续记录 |
| 每条轨迹的控制记录 | **149 帧** | 15 Hz，每个回合约 9.93 秒；可能包含首次成功后的保持/退出动作 |
| 所有轨迹的逐帧记录 | **56,024 条** | 376 × 149；连续帧相关，不能把它们当成 56,024 个独立任务回合 |
| 成功/失败回合 | **367 / 9** | 是专家采集时的表现，不是你以后训练出的算法成功率 |
| 采集批次 | **20 批** | 根目录那些编号文件夹，每批里包含多个回合 |
| NumPy 数组文件 | **5,640 个** | 每回合 15 个文件，合起来才组成该回合的完整记录 |
| 原有文件总大小 | **11,042,682,017 字节，约 11.04 GB** | 不含本说明文档；大部分空间是未压缩 RGB 图像 |

**如果你问“有几条示教”，答案是 376 条轨迹；如果你问“有几条逐帧样本”，答案是 56,024 帧。不是 20 条，也不是 5,640 条。**

## 一帧到底包含什么

第 `t` 帧可以理解成：

**执行动作前的图像 + 末端状态 + 六维力 + 运动信息 + 上一步指令 → 专家这一步提交的动作。**

同一回合的不同 `.npy` 文件，以相同的时间下标 `t` 对齐。它们不是 15 份不同数据集。

下面的形状是每个完整回合的实际形状，已检查全部 376 个回合均一致：

| 文件 | 形状 | 类型 | 内容和时间含义 |
|---|---|---|---|
| `rgb.npy` | `(149,256,256,3)` | uint8 | 动作前的 149 张 RGB 图像；图像像素直接存于数组，不是图片路径 |
| `state.npy` | `(149,8)` | float32 | 动作前末端 xyz 位置（m）、wxyz 四元数、夹爪开度（m）；位姿含观测噪声，不是机械臂关节角 |
| `wrench.npy` | `(149,6)` | float32 | 动作前因果平滑后的 `[Fx,Fy,Fz,Tx,Ty,Tz]`，单位 N、N·m，incoming-joint 参考系 |
| `motion.npy` | `(149,6)` | float32 | 动作前有限差分得到的末端线速度和角速度，m/s、rad/s |
| `previous_command.npy` | `(149,4)` | float32 | 动作前已知的上一条四维指令 |
| `action.npy` | `(149,4)` | float32 | 专家当前提交、EMA 平滑前的归一化 `[x,y,z,yaw]` 指令；不是关节角或直接以米为单位的位移 |
| `ema_action.npy` | `(149,7)` | float32 | 当前动作经 stock EMA 后的七维执行布局；含约束维度，第七维不是夹爪指令 |
| `target_position.npy` | `(149,3)` | float32 | 当前动作下发的末端位置目标，m |
| `target_quaternion.npy` | `(149,4)` | float32 | 当前动作下发的末端姿态目标，wxyz |
| `raw_wrench.npy` | `(149,6)` | float32 | 当前动作执行后最后一个物理子步的原始六维载荷 |
| `substep_wrench.npy` | `(149,9,6)` | float32 | 前一控制边界值 + 本步 8 个物理子步的载荷；第 0 项是重复边界，不能重复加权 |
| `observed_after_state.npy` | `(149,8)` | float32 | 当前动作执行后的状态，在自动重置前捕获 |
| `stable_success.npy` | `(149,)` | bool | 当前步是否达到连续三步的几何成功判据 |
| `terminated.npy` | `(149,)` | bool | 当前转移的终止标记 |
| `truncated.npy` | `(149,)` | bool | 当前转移的截断标记 |

动作后的目标、状态和载荷是结果/审计信息，不能在预测当前动作时当成已经知道的输入。训练模型也不必把这 15 个字段全都作为输入。

`.npy` 是 NumPy 数组文件格式，可直接读取数字和图片像素，但文件管理器不会自动展示内容。当前目录把一条轨迹拆成多个对齐数组，因此需要本说明和总索引才能直接理解；文件数量本身不是样本数量。

## 不训练任何算法，直接读一个样本

在项目根目录使用原 Python 环境执行：

```python
from pathlib import Path
import numpy as np

episode = Path('data/act_demonstrations/00_train_1100/train-1100-000000')
rgb = np.load(episode / 'rgb.npy', mmap_mode='r', allow_pickle=False)
state = np.load(episode / 'state.npy', mmap_mode='r', allow_pickle=False)
wrench = np.load(episode / 'wrench.npy', mmap_mode='r', allow_pickle=False)
action = np.load(episode / 'action.npy', mmap_mode='r', allow_pickle=False)

print('这个回合的帧数:', len(action))
print('第0帧图像形状:', rgb[0].shape)
print('第0帧末端状态:', state[0])
print('第0帧六维力:', wrench[0])
print('第0帧专家动作:', action[0])
```

已有可直接观看的副本位于相邻目录 `../preview/train-1100-000000/rgb.mp4`，另有第 0、74、148 帧截图。视频只是便于观看的副本；原始图像位于 `rgb.npy`。

## 范围和缺少的字段

这批是仿真示教，不是真实机器人采集。现有文件没有完整的关节位置/速度序列，没有独立的奖励数组，也不是完整的物理引擎接触检查点。算法若需要这些额外字段，需明确适配或另外采集，不能只凭目录改名就认为已经具备。

历史接口和回放审计的完整说明位于项目根目录 `DATA_FORMAT.md` 以及 `reports/replay_root_cause_20261027/`。本次新增说明没有移动、删除、重编码或重新划分任何原始数据。
